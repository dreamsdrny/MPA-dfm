# MPA-DFM 代码安全与数据可靠性审查

审查对象：当前工作树，2026-11-24；侧重正式 `mpa_dfm.py` 工作台、输入解析、
DFM/SMT、报告、Allegro 桥接/阻抗插件和授权发布。未对客户 BRD/现有交付做写操作。

## 范围与结论

- 本项目扫描到 `src/`、`tools/`、`skill/` 合计约 168 个 Python 文件和 2 个 SKILL/form 文件。
- 已做全树危险 API/导出/异常处理检索和关键路径人工审阅，**不等于逐行形式化审计或保证没有其他漏洞**。
- 本轮测试：`python -X utf8 -m pytest tools -q`：**293 passed、17 subtests passed**；
  高危语法/名称 Ruff 规则通过。专项测试只能覆盖测试过的情形，不能推断真实 CAD 兼容。
- 使用临时目录的最小复现验证了下面标记为“已复现”的问题；未启用第三方漏洞扫描、依赖 CVE 在线核验、模糊测试或商用 CAD 真板验证。
- 无本轮代码修复；这是修改前的问题清单。完整 DRC/阻抗计算、真实 CAD 验收、部署矩阵本来就未完成。

## P0 / 高优先级

### A01 不可信网络名可注入自动执行的 SKILL（已复现）

- 位置：`src/skill_generator.py:35-43, 49-105, 121-122`；调用：`main.py:171-179, 757-785`。
- Jinja 模板把 Net/差分对/约束名称和数值直接插入 SKILL，缺少引号转义、控制字符过滤和数值验证。输出脚本末尾自动调用创建约束函数。
- 临时复现的 Net 名 `N") (printf "INJECTED_CODE\n") (printf "` 被原样插入，可改变解释器表达式结构。
- 前提：使用受控/不可信网络资料生成脚本，再由操作员在 Allegro 加载该生成脚本；不是声称仅导入 BRD 就执行。
- 建议：所有 SKILL 字符串统一编码；所有数值严格有限数验证；删除生成脚本的自动执行尾部并要求二次确认；相关导出先标记不可信，添加注入回归和真实 API 验证。

### A02 压缩数据解压前无预算，可能内存耗尽（已复现）

- 位置：`src/brd_design.py:46-76` 直接 `zlib.decompressobj(...).decompress(blob)`；`src/design_geometry.py:43-62` 直接 `ZipFile.read()`；`src/design_inputs/archive.py:96-104` 在 `unlzw()` 完成后才检查大小。
- 临时构造约 3 KB 的压缩条目，成功膨胀到 3 MB；另一快照约 5 KB 膨胀到 5 MB；代码没有解压前/过程中截断。输入可继续放大，导致内存/CPU 资源耗尽。
- 建议：统一压缩输入、单条、总量、条目数预算；流式限量解压；Unix `.Z` 使用可限制输出的解码器/受限子进程；超限直接报告未完成，绝不当作无问题。

### A03 外部 Gerber/补充资料分析缺内容一致性门禁（已复现服务路径）

- `src/services/pcb_analysis.py:38-66, 70-100` 只在前后检查 BRD 路径/大小/mtime 和 PCB 能力 YAML 哈希；外部 Gerber 分支没有资料内容哈希前后比对，补充 JSON/坐标也没有统一末端复核。
- 模拟外部分支在分析期间改写 Gerber，`run_pcb_analysis` 仍返回 `external_gerber` 结果；这是服务边界缺陷复现，不等同已在真实制造文件测出错误数值。
- `src/brd_input.py:9-26` 的 BRD 签名也是路径/大小/mtime；同长内容替换并恢复 mtime 可绕过，已复现。`src/pcb_geometry_data.py:65-74` 对部分 Gerber `source.json` 同样只检查大小/mtime。
- 建议：分析前后按内容哈希验证 BRD、每个相关制造文件/坐标文件/补充 JSON；记录覆盖的文件清单；导出报告前再次校验快照。不要把文件状态签名描述为密码学内容证明。

### A04 自动覆盖外部资料目录中的预览和报告侧文件（已复现）

- `src/services/pcb_analysis.py:100` 将固定名 `DFM_Gerber_preview.html` 写到用户选定的 Gerber 目录；`src/gerber_analysis.py:569` 直接覆盖。临时目录复现了原有同名文件被覆盖。
- `src/workbench_report.py:227-231` 导出 `report.xlsx` 时以 `os.replace` 自动覆盖 `report.txt` / `report.json`；UI `src/ui/dfm_dialog.py:1184-1192` 的保存对话框只确认主目标。临时复现新 XLSX 名称对应的已有 TXT 被覆盖。
- 建议：预览写入独立应用输出目录；报告先列出所有目标文件、分别确认或使用新目录/唯一命名，提交期间避免半套 sidecar；禁止目标与输入资料相同。

### A05 综合 DFM CSV 会缺失 SMT（已复现）

- `src/workbench_report.py:281-288` 的 `for kind, stage ...` 覆盖了报告类型局部变量；`312` 行再判断 `kind in ("smt", "dfm")`。
- 复现包含原生 Gerber stage 的 DFM 综合 CSV，文件仅有 PCB 范围，无 SMT 行，却没有报错。无 stage 时不触发这一特定缺陷。
- 建议：改局部变量名，覆盖 `pcb/dfm/smt` × 有/无导出阶段的矩阵，检查生成 CSV 记录与控制台/工作簿一致。

### A06 Excel 可解释外部字符串为公式（已复现）

- `src/design_inputs/bom.py:299-312`、`src/workbench_report.py:267-279`、`src/net_locate.py:625-659` 和 `src/brd_analysis/writers.py:480-505` 写 CSV 时直接输出外部字符串。
- 临时 BOM 的料号 `=1+1` 和报告板名 `=2+2` 均原样出现在 CSV。用户用 Excel 等电子表格打开时存在公式解释/外链风险；并非声称运行程序本身就执行公式。
- 建议：建立统一的“供电子表格打开的 CSV”安全转义（含前导空白、`= + - @`、制表符等）；同时保留明确标识的原始机器数据导出，不破坏 Net/BOM 原值。

### A07 `.brd` 后备识别可把普通文本当设计（已复现）

- 主工作台 `src/ui/dfm_dialog.py:942-950` 在新解析失败后退回 `src/pcb_reader.py`，再由 `src/brd_input.py:30-37` 接受任何非空 layers/layer_count/nets。
- 临时文本文件内容仅含 `LAYER_NAME='TOP'`、后缀 `.brd`，经 `extract_brd_info` 和 `validate_brd_info` 被接受。存在误导用户“BRD 已导入”的风险；不代表它能通过全部制造放行门槛。
- 建议：引入可验证文件头/版本与结构证据，模糊旧版识别只作为“未验证旧格式”，不允许直接启用正式报告/分析；保留清晰缺口。

### A08 SMT 配置重复键静默覆盖、配置变更不可追溯（已复现）

- `src/smt_engine.py:33-36, 97-98` 用 `yaml.safe_load`，不同于 PCB 的重复键拒绝逻辑；重复 `value: 0.1` / `value: 0.01` 被接受并以 0.01 生效。
- 配置只记录路径/修订，没有 SHA-256；`src/ui/smt_panel.py:182-196, 312-325` 只在有对象证据时检查证据来源，不检查厂商 YAML/内部基线变化。修改文件后仍用旧内存规则和同一文件路径，已复现。
- 建议：统一拒绝重复 YAML 键；读取时保存实际字节哈希，分析前后及报告导出前检查供应商/内部基线版本。

## P1 / 中高优先级

### A09 原生插件仅用板名防换板，目录数据未绑定文件内容

- `skill/imp_highlight.il:213, 321-325, 384, 454` 以 `axlCurrentDesign()` 名称和固定插件 token 做检查。Cadence 本机手册 `14dsnctl.html:74-81` 明确该函数返回**设计名称**；`axlGetDrawingName()` 才返回完整路径。
- 因此不同目录同名板可能通过名称检查；同一板的未保存编辑/替换也不能由 token 证明未变化。此为代码和官方 API 合同推论，**没有真实 CAD 切板复现**。
- `src/impedance.py:11-42` 只校验 token、记录数、完成文件读前后文本；修改 CSV 某行但不改变行数可通过，已用临时数据复现。标记相同内容的并发重写也无法区分。
- 建议：引入 `axlGetDrawingName`、设计会话/变更戳、唯一导出批次、CSV 内容哈希及严格版本边界；未保存设计必须提示并重测；token 不应充当认证。

### A10 阻抗证据有未解析覆盖时仍可标为 IMPEDANCE（已复现 SKILL 模拟）

- `skill/imp_highlight.il:125-157, 176-178, 348-350` 只要有一个可解析 target 且没有多个数值，就返回 `IMPEDANCE`；同一个 Net 的无法解析 pin-pair 覆盖被追加到 raw 文本但不阻断。
- 使用 Cadence `cnskill` + 模拟 API：Net 目标 `ALL:ALL:100:5` 同时有 flattened `P1:P2:90:5`，结果仍为 `IMPEDANCE`、target 100。模拟验证的是逻辑，真实 override 格式/作用域仍需 PCB Editor 验收。
- 建议：有未解析或无法绑定到 Segment 的潜在阻抗覆盖时为 `UNRESOLVED`，不作为已确认 100 Ω 识别；或者实现完整作用域映射及冲突证明。

### A11 Excel 网络定位走线长度、宽度可能不是实际值

- `src/allegro_skill.py:234-265` 逐段取宽度失败时沿用上一个段的 `w`，而导出所有直线/圆弧都标为 TRACE、只含端点；`src/net_locate.py:115-128` 一律用端点直线距离作为长度。
- 缺段宽会被冒充成前段宽；圆弧长度通常大于弦长。没有真实 CAD 数据时无法断言某块板已触发，但逻辑风险明确。
- 无单位首行的 CSV 在 `src/net_locate.py:84-102` 默认 millimeters/1000；已复现不带 UNITS 的 `WIDTH_UU=5` 被当 5 mm，不知道源单位是 mil 还是 mm。
- 建议：段级字段缺失保持 unknown；导出 arc 类型和圆心/扫角或 CAD 精确长度；无明确单位拒绝数值测量。

### A12 屏幕拾取跨回调保留 dbid，仍需 CAD 实测

- `skill/imp_highlight.il:397, 484-503` 将 segment dbid 存到全局 `imp_results`，后续表单拾取回调使用，再 `axlDBRefreshId`。板编辑/命令上下文变更可能让 dbid 失效或属性陈旧；点击时只核验当前对象，没有证明最近邻未变化。
- 当前 `imp_clear()` 清除全局 `imp_results`，但另一个设计名称相同或后台编辑仍需明确区分。需真实 CAD 的 callback 生命周期、错误回滚、可选层隐藏、临时高亮、拾取/空层与许可证验收；模拟不等于实机成功。
- 建议：记录稳定对象身份/坐标/Net 并在回调中重新查询或设置只读/变更锁；必要时重新测量，失败显式不可用。

### A13 快照圆弧强制短弧（已复现）

- `src/design_geometry.py:87-123`、`src/brd_analysis/geom.py:129-152` 把扫角规范到 ±π；已有 `start=0,end=3π/2` 输入得到 π/2 的长度和短弧。
- 若源数据允许超过 180° 弧或指定方向，板框/长度/间距候选可能错误。当前尚未用真实 Allegro 长弧确认快照语义，因此是明确算法缺口，不断言所有真实 BRD 都受影响。
- 建议：读取方向/半径/扫角的原生语义；缺信息保持未知，不标“精确弧长”，覆盖大于 180°、跨 0、顺逆时针和整圆。

### A14 SMT 同一字段多条能力规则的内部对比只保留最后一条（已复现）

- `src/smt_engine.py:188-190` 用 `(scope, field)` 构造字典，覆盖前面同字段规则；而配置加载仅校验维度一致、没有禁止相同字段多规则。
- 合成两条 `>=2` 和 `>=0.5`，基线 `>=1` 时对比只展示后者并返回覆盖；不代表其他独立逐项检测一定丢失。
- 建议：多规则显式合并为允许区间交集或逐条展示，不可用字典静默覆盖；加顺序置换测试。

### A15 关闭窗口不会取消后台工作，报告/导出可能继续写文件

- `src/ui/tasks.py:26-34, 77-85` 为 daemon 线程，`close()` 仅停止回调并清空 pending，不终止工作；`src/ui/dfm_dialog.py:1001-1015` 在主工作台任务进行时直接关闭。
- 结果是用户关闭窗口后，仍有可能生成/覆盖导出文件，或进程退出时任务半途结束。受调用时机影响，尚未做真实 CAD 进程中断实验。
- 建议：任务区分可取消/不可取消；关闭前提醒等待或明确取消；仅终止本进程树，不终止用户其他 PCB Editor；保证生成输出事务化。

## P2 / 质量、性能和运维

### A16 扫描预算不覆盖解码和单次空间查询内存

- `src/layout_geometry.py:86-95` 先 `STRtree.query` 返回某对象全部邻居，再逐条计数预算；极密集单次查询可能先分配大量内存。Gerber/ODB 解析及布尔合并也发生在部分候选预算之前。
- 建议对输入大小、图元数、单次查询/数组内存、壁钟时间分阶段限额，超限写 coverage=incomplete；不要把“有候选预算”描述为全链路资源安全。

### A17 HTML 预览对部分字段不统一转义（合成输入复现）

- `src/gerber_analysis.py:560-563` 转义 item/layer/unit，但直接插入 `x/y/measured/capability`；直接调用 `write_preview` 时，合成的 `measured='<img ...>'` 原样进入 HTML。
- 正常几何管线很多值来自数值计算，此处尚未证明不可信实际输入能流到该字段，按**条件性注入风险**处理，不宣称已存在外部远程执行链。
- 建议所有展示字段先数值化或 `html.escape`，并对属性值转义；增加安全预览模板测试。

### A18 结果校验与展示行为不一致

- `src/impedance.py:76-88` 最小字段合同不要求 `BRD`、坐标、单位；构造含 1 行的简化 CSV 已被 `read_results` 接受。`src/ui/impedance_panel.py:213` 有 catalogue 时才尝试比对 BRD；无 catalogue 时可能显示数据。
- `src/ui/impedance_panel.py:176-183, 218-223` 只渲染前 2000 项，规则列表不标明截断数量。建议严格字段/版本校验、分页/筛选与可见覆盖提示，不把展示截断当作结果缺失或全量。

### A19 文档/版本与授权使用边界

- `docs/ARCHITECTURE.md:164-204` 标注了已废弃旧方案，但后文仍残留旧文件路径和 mailbox 说明；`docs/ACCEPTANCE_TESTS.md:97-111` 有类似历史段落，易让新维护者引用错误入口。
- 当前交付为离线签名许可，依赖本机日期；无可信时间/在线吊销/Windows Authenticode。**这是已记录设计限制，不是已证明的签名绕过。**
- 建议重整“当前”和“历史”文档；正式发版补依赖锁文件、第三方漏洞扫描、受控许可私钥备份和企业终端/杀毒/签名验收。
