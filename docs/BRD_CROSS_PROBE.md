# 打开真实 BRD 与问题点联动定位

## 操作步骤

1. 运行最新 `dist/MPA_DFM.exe`，选择当前 BRD、板厂和制程等级。
2. 点“打开 BRD 并提取坐标”，完成 Allegro 许可/产品选择后等待自动分析。
3. 双击制程能力比对中的 FAIL/WARN 行，进入相应问题坐标。
4. 点“打开 BRD 定位”或双击有坐标的行。
5. 状态显示“Allegro：已定位选中问题点”；勾选“选点同步到 Allegro”后用上/下一个点继续查看。
6. 勾选“并排显示”可左右对照两个程序。

## 器件 X/Y 与任务栏图标修复

- “打开 BRD”现在也自动提取坐标；完成后直接切到“BRD 器件 X/Y (数量)”页签。
- 器件页包含位号、X/Y(mm)、X/Y(BRD)、单位、面、旋转、来源；双击可定位真实器件原点。
- 输入变化只作废制造结果，不清除同一 BRD 的器件坐标；换板则清除。
- 坐标持久保存到 BRD 同目录 `定位清单/allegro_bridge`，重新打开程序可读取。
- PCB/DFM 报告新增全量器件坐标。
- 原横排 evan 图标缩到任务栏不可读；新版采用 EV/AN 两行，9 种原生图标尺寸并按 DPI 设置窗口图标。
- 本机实测主界面显示 **279 个器件原点**；C1 为 X=31.242mm、Y=6.096mm（1230mil、240mil），点击后得到 LOCATED 回执。
- 本轮 57 项测试全部通过，静态检查通过；新版 `dist/Evan_MPA_DFM_20261112_XY.exe` 已生成并启动验证。旧 MPA_DFM 运行中，故未覆盖它。

首次未检测到 Editor 时，通过“设置 PCB Editor”指定 `allegro.exe`。无对象级坐标的板级工艺项仍显示缺失原因，不能凭规则数值生成位置。

## 本轮变化

- 页眉删除 Checklist、器件统计按钮，增加打开 BRD。
- 同一已连接 BRD 重用 Editor 进程；后续点位使用数字邮箱与 SKILL 定时器同步。
- 输入为 mm，在 Editor 内用 `axlDBGetDesignUnits` + `axlMKSConvert` 换算，不受用户切换 mil/mm 影响。
- `axlZoomPoints` 缩放到问题坐标周围；BRD 源文件不被修改/保存。
- 自动导出采用文档中的 symbols/pins、net/branch/children，而非无效的 design.vias/clines。
- 孔径优先取 padstack 的实际 drillDiameter；非通孔不混入机械通孔匹配。
- 修复旧 SKILL 多参数 setq、操作符前缀、return/prog、nil 字符串导致的中断。

## 实机验证

环境：Windows 11，Allegro 17.4 S030；真实文件 `S-860-000000_FAB_BRD_Rev_E.brd`。

- 真实 BRD 打开并建立 READY 连接。
- 自动导出：279 元件、589 过孔、7 通孔引脚、671 引脚外框、2308 走线段。
- 同一会话发送两个不同 mm 坐标：均回执 LOCATED。
- 用实机导出接入制造分析得到问题点，首个示例 mm=(5.334,6.096)、mil=(210,240)。
- GUI 端到端验证：自动打开/导出/重新分析得到 671 条可定位问题记录，点击问题点收到 LOCATED；Windows 并排排列返回成功。
- 本轮测试：54 项通过、1 项 Tk 环境临时跳过；单独运行工作台 UI 5 项全部通过。打包 EXE 已重建并启动/关闭冒烟通过。
- 新增启动参数/坐标邮箱/真实孔径/无坐标输入以及 GUI 双击跳转测试。

同步定时器在 Editor UI 处理消息时工作；交互命令或产品选择未完成时可能延迟。显示“待响应”应结束当前交互，再次选点。程序只排列自己启动的窗口，不接管其他手工打开的 Editor 实例。
