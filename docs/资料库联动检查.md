# 资料库联动检查（store-brd / store-bom）

把 `.brd` 和 BOM 按固定目录摆好，程序自动配对、逐位号双向核对、出报告。
不替代人工判断：只报差异，不自动改 BRD 或 BOM。

```
<程序目录>/
├─ store-brd/    Allegro .brd（可另放 place_txt.txt / evan_components.csv 补位号）
├─ store-bom/    BOM 表（.xlsx / .csv）
└─ output/       报告默认落在这里
```

## 怎么跑

| 入口 | 操作 |
|---|---|
| 界面 | `Evan_BRD.exe` → 底部「BRD↔BOM 联动检查」→ 确认目录 →「开始检查」→「导出报告」 |
| 命令行 | `python main.py --store-check` |
| 指定目录 | `python main.py --store-check --store-root D:\proj --store-out D:\proj\out` |
| Python | `from src.design_inputs import run_check; bundle = run_check(brd_dir=..., bom_dir=...)` |

界面里两张表：**配对结论**（每对一行，含结论与匹配依据）、**位号明细**（选中那一对的逐位号结果，
可按「只看差异 / 只看未核对」筛选），下方详情区列出该对的每一项检查与差异样例。

## 配对规则

从强到弱，只认能证明的对应关系：

1. **料号**：BOM 某行的料号等于 BRD 文件名的料号。
   例：`S-860-000000_FAB_BRD_Rev_E.brd` ↔ BOM 里 `PCB1` 行 `IPN = S-860-000000`。
2. **数字核**：两个文件名共享 ≥5 位数字串。
   例：`S-860-000000_...brd` 与 `S-850-000000_BOM_REVG...xlsx` 共用 `000739`。
3. **配不上**：列为「未配对」并写原因，不强行配对。

同一文件不会被重复配对；多候选取分数最高的一对（料号相同还会给版本相同的候选加分）。
BOM 只支持 `.xlsx` / `.xlsm` / `.csv`；`.xls`（97-2003）请先另存为 `.xlsx`。

## 核对项

| 检查项 | 通过 | 需确认 / 数据不足 |
|---|---|---|
| BRD 读取 | 归档可解析，能读到层数/板框等设计量 | BRD 损坏或不是 Allegro 17.x 归档 → 不符合 |
| BOM 读取 | 位号数 > 0，表头识别成功 | 完全读不出位号 → 不符合 |
| BOM 数据质量 | 位号无重复，数量与位号数一致 | 数量不符、重复位号、空位号行（`warnings`） |
| 料号一致 | BRD 文件名料号出现在 BOM 料号列 | 不在 → 需确认；文件名看不出料号 → 数据不足 |
| 版本一致 | 两侧文件名版本号相同 | 不同 → 需确认（FAB 图与装配 BOM 版本口径可能不同） |
| BRD 位号清单 | 有 `objects/Part.xml` 或同目录导出文件 | 都没有 → 数据不足，并提示补法 |
| 位号双向核对 | `verified`（位号集合一致且无属性冲突） | `incomplete` / `review` → 需确认 |
| 非电气项 | — | 仅信息：`PCB1`、`SCH1`、`ASSYDWG1`、`SOLDER_PASTE2` 等不参与核对 |
| BRD 设计量 | — | 仅信息：最小线宽 / 最小间距 / 最小钻孔 / 板厚 |

**位号核对结论**（与 `--bom` 同一套口径）：

- `BOM 漏项`：BRD 有位号、BOM 未列 → 优先按 BOM 漏项处理；
- `BOM 多出`：BOM 有位号、BRD 未列 → 可能是 DNP、机构件、替代料、版本串用，**必须人工确认**；
- `属性冲突`：双方都有但封装/料号/MPN/值不同 → 只报差异，不判哪边正确；
- `未核对`：BRD 没有位号清单时，BOM 的每个位号仍逐行列在明细里，状态为未核对。

非电气项（`PCB1`、`SCH1`、`ASSYDWG1`、`SOLDER_PASTE2`，以及 `FID`/`MH` 等）按位号前缀识别，
不参与核对；但只要该位号出现在 BRD 的 `objects/Part.xml` 里，就仍按元器件核对 ——
有些板子把 `MH1` / `FID1` 当器件放进设计，不能只凭前缀排除，否则会刷出假的「BOM 漏项」。

版本号、料号、位号来源缺任何一项都只会拉低结论（需确认 / 数据不足），不会因为「文件配对成功」
就报通过。

## 没有 `objects/Part.xml` 的 BRD（FAB 拼板图）

`S-*_FAB_BRD_Rev_*.brd` 这类图档只有板框、钻孔和约束对象，没有器件位号。此时：

1. 报告写「数据不足」，并说明原因；
2. 把 Allegro 导出放到 **`store-brd/` 同目录**（不必改名，按内容识别）：
   - `File > Export > Placement` 得到的 `place_txt.txt`（推荐）；
   - 或 SKILL 导出的 `evan_components.csv` / `evan_pads.csv`；
   - 脚本可以先生成：`python main.py --export-skill .\out\allegro_bridge`，把生成的
     `.il` / `.scr` 里的路径改成本机后在 PCB Editor 里跑；
3. 重新检查，BRD 侧位号来源变为「Allegro Placement / SKILL 导出」，逐位号核对恢复；
4. 更彻底的做法：改用带 `objects/Part.xml` 的设计 `.brd`（真实 PCB 设计一般都有）。

导出文件的封装名与 BOM 的 `PCB Footprint` 同为 Allegro 封装名，可直接比较；值/料号 BOM 有而
BRD 没有，按「任一侧为空不做冲突判定」处理，不会造假差异。

## 报告

`BRD_BOM联动检查_<时间>.xlsx`：

| 页签 | 内容 |
|---|---|
| 总览 | 生成时间、总体结论、目录、文件数、配对与各状态计数、警告 |
| 配对结论 | BRD/BOM 文件、料号、版本、位号数、位号核对状态、结论、匹配依据 |
| 检查项 | 每一对的逐项检查与说明（通过/需确认/不符合/数据不足） |
| 位号核对 | 逐位号合并视图：状态、在 BRD/在 BOM、面别、DNP、封装、料号、MPN、值 |
| 差异明细 | BOM 漏项 / BOM 多出 / 属性冲突 / 非电气项 |
| 未配对 | 没配上的文件与原因 |

同目录还会写 `.txt`（人读）、`.html`（带颜色的表格）、`.json`（完整数据，供二次处理）。
JSON 里每一对包含 `checks`、`reconciliation.rows`、`bom_items`，字段稳定。

## 边界

- 只读资料，不修改 `.brd` / BOM，也不会自动「修复」差异；
- 不解析图形几何，位号/属性判定只依据归档对象与 BOM 表格；
- 版本号取自**文件名**（`Rev_E`、`REVG`），不是图纸标题栏；
- 非电气项不参与位号核对，但仍列在报告里，避免被当作漏项统计。
