# 多格式输入框架

BRD 是必需的主资料；其约束、元数据和可解析快照保存在 `primary`。补充资料分别保存在 `supplements`，记录路径、文件 SHA-256、格式、状态和警告，不覆盖 BRD，也不假定不同文件属于相同版本或坐标系。目录目前不计算整体哈希。坐标和长度以 mm 标记，BRD 快照保留原始单位，几何标定方法和置信度见 `primary.geometry`。

```shell
python main.py --input-project demo/DEMO_BOARD.brd --bom full_bom.xlsx --supplements board.gtl assembly.step odb.tgz --input-json inputs.json
```

Python 接口：`load_project(brd_path, supplements)`；需要指定格式时使用 `[('gerber', path), ('bom', path)]`。`register_adapter(kind, callable)` 可接入自定义解析器，输入路径，返回包含 `status`、`warnings` 及格式数据的字典。BRD 无法解析时抛异常；补充资料独立报告 `error`，CLI 此时退出码为 1。`parsed` 为该适配器当前支持的子集已读取；`partial` 表示部分读取；`unsupported` 表示未能解析该格式。状态不是制造数据完整性认证。

## 当前实现

* BRD：复用现有 Allegro 约束/原始信息及内嵌快照解析器；并非所有 BRD 版本或全部几何都可解析。
* Gerber：X2 FileFunction 优先，其次常见扩展名判断层角色；读取 RS-274X 的单位、绝对坐标、常见孔径、移动、绘制、圆弧、闪光、区域标记及极性。几何是 CAM 原语，不是已展开或布尔合并的最终铜面；宏、步进重复等复杂功能只报告警告。层名无法识别时为 `unknown`。
* BOM：CSV 与 Excel（`.xlsx`）导入，导入后自动与 BRD 位号清单逐项核对。Excel 会在表头区（前 60 行）找含位号列的那一行，因此带标题/页码/分隔行的 Cadence `Bill Of Materials` 报表可直接导入；`Part Reference`、`PCB Footprint`、`IPN`、`MPN`、`Quantity` 等表头自动归一化。CSV 保持严格口径（数量不符、位号重复报错），Excel 宽容（收进 `warnings`，供核对报告展示）。OrCAD Capture 的专有 DSN 不直接当作 BOM，须从 Capture 导出后导入。
* ODB++：识别目录、ZIP、TAR/TGZ 的 `matrix/matrix` 根、step、layer 和 `misc/info` 中声明的版本；不解压归档，不解析 features。版本未知时不会猜测。
* STEP/STP：识别 ISO-10303-21 文件、schema 和实体类型计数；机械体、高度、装配空间需接入三维 CAD 内核，当前为 null。

## BRD 与完整 BOM 核对

BRD 能可靠给出位号，并从 `objects/PartDefn.xml` / `objects/Gate.xml` 防御式提取封装；完整 BOM 补齐值、封装、料号、面别与 DNP。`load_project(..., supplements=[bom.csv])` 会自动生成 `bom_checks`，每个 BOM 补充项也有 `reconciliation`。核对是双向的，不自动修改 BRD 或 BOM：

* `missing_in_bom`：BRD 有位号、BOM 未列，优先按 BOM 漏项处理，状态为 `incomplete`。
* `missing_in_brd`：BOM 有位号、BRD 未列，可能是 DNP、机构件、替代料或版本串用，状态为 `review`，必须人工确认。
* `conflicts`：双方都有该位号，但封装/料号/值规范化后不同；只报告差异，不判定哪边正确，状态为 `review`。
* `verified`：位号集合一致且无属性冲突；`unavailable`：BRD 没有可用的 Part.xml 位号清单，不能判断 BOM 缺漏，BOM 行标记为 `unverified`。
* `fields_compared` 当前列出 `footprint`、`part_number`、`manufacturer_part_number`、`value`；任一侧为空时不做冲突判定。
* `rows` 给出逐位号合并视图，状态为 `matched` / `missing_in_bom` / `missing_in_brd` / `conflict` / `unverified`，保留 `brd`、`bom` 原始记录、`side`、`dnp` 和核对状态，供后续 SMT 资料扩展使用。

```python
from src.design_inputs import load_project, reconcile_bom
project = load_project("board.brd", ["full_bom.xlsx"])
check = project["bom_checks"][0]["reconciliation"]
print(check["status"], check["summary"])
```

补充 BOM 的条目会额外带 `non_electrical`（非电气项列表）和 `reconciliation`（仅对元器件行做
双向核对）。`PCB1`/`SCH1`/`ASSYDWG1` 这类非电气项不参与位号核对；BRD 里存在的位号一律按元器件
处理（例如有些板子把 `MH1` 放进 `objects/Part.xml`，不会被前缀误排除）。

## 资料库联动检查（store-brd / store-bom）

除手工传路径外，还可以按目录约定批量核对：把 `.brd` 放进 `store-brd/`、BOM 放进 `store-bom/`，
`python main.py --store-check` 或主窗口「BRD↔BOM 联动检查」会自动配对、逐项核对并输出报告。
配对优先用 BOM 行料号匹配 BRD 文件名料号，其次用文件名共用的数字核；非电气项（`PCB1`、`SCH1`、
`ASSYDWG1`、`SOLDER_PASTE2` 等）不参与位号核对。BRD 没有 `objects/Part.xml` 时，同目录的
`place_txt.txt` / `evan_components.csv` 可作为位号来源；都没有则报告「数据不足」并给出补法。
详见 [资料库联动检查](资料库联动检查.md)。

## BOM 导入导出合同 v1

字段固定为 `refdes,part_number,value,footprint,description,manufacturer,manufacturer_part_number,side,dnp`，一行对应一个位号，除 refdes 外可为空。导入支持 CSV 与 Excel（`.xlsx`/`.xlsm`）：CSV 按 UTF-8（允许 BOM 标记）、逗号分隔读取；Excel 在前 60 行内找含位号列的表头行，`Part Reference`、`PCB Footprint`、`IPN`、`MPN`、`Quantity`、`位号`、`封装`、`数量`、`不贴`、`厂商料号` 等别名自动归一化，`Item`、`Schematic Page`、`备注` 等已知无关列忽略。含多个位号的单元格使用逗号、分号、斜杠、竖线或空白分隔；数量列如果存在应等于位号数。`R1-R4` 这类范围写法不展开，按单个位号处理并在 `warnings` 中提示。位号大小写不敏感且不可重复。

质量口径：完全读不出位号时抛 `ValueError`；数量不符、重复位号、位号为空的行，`strict=True` 报错，`strict=False`（Excel 默认）记为 `warnings` 并保留可读的行，供核对报告展示。未知列暂不保留；变体与替代料需后续扩展合同。

```python
from src.design_inputs import import_bom, read_bom, export_bom
rows = import_bom("bom.xlsx")            # 只要行
info = read_bom("bom.xlsx", strict=False)  # 行 + 表头识别 + 质量提示
export_bom("bom.csv", rows)              # 导出 UTF-8 BOM CSV, Excel 直接打开
```
