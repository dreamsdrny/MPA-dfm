# 多格式输入框架

BRD 是必需的主资料；其约束、元数据和可解析快照保存在 `primary`。补充资料分别保存在 `supplements`，记录路径、文件 SHA-256、格式、状态和警告，不覆盖 BRD，也不假定不同文件属于相同版本或坐标系。目录目前不计算整体哈希。坐标和长度以 mm 标记，BRD 快照保留原始单位，几何标定方法和置信度见 `primary.geometry`。

```shell
python main.py --input-project demo/DEMO_BOARD.brd --supplements board.gtl bom.csv assembly.step odb.tgz --input-json inputs.json
```

Python 接口：`load_project(brd_path, supplements)`；需要指定格式时使用 `[('gerber', path), ('bom', path)]`。`register_adapter(kind, callable)` 可接入自定义解析器，输入路径，返回包含 `status`、`warnings` 及格式数据的字典。BRD 无法解析时抛异常；补充资料独立报告 `error`，CLI 此时退出码为 1。`parsed` 为该适配器当前支持的子集已读取；`partial` 表示部分读取；`unsupported` 表示未能解析该格式。状态不是制造数据完整性认证。

## 当前实现

* BRD：复用现有 Allegro 约束/原始信息及内嵌快照解析器；并非所有 BRD 版本或全部几何都可解析。
* Gerber：X2 FileFunction 优先，其次常见扩展名判断层角色；读取 RS-274X 的单位、绝对坐标、常见孔径、移动、绘制、圆弧、闪光、区域标记及极性。几何是 CAM 原语，不是已展开或布尔合并的最终铜面；宏、步进重复等复杂功能只报告警告。层名无法识别时为 `unknown`。
* BOM：CSV 导入导出；OrCAD Capture 的专有 DSN 不直接当作 BOM，须从 Capture 导出 CSV 后导入。
* ODB++：识别目录、ZIP、TAR/TGZ 的 `matrix/matrix` 根、step、layer 和 `misc/info` 中声明的版本；不解压归档，不解析 features。版本未知时不会猜测。
* STEP/STP：识别 ISO-10303-21 文件、schema 和实体类型计数；机械体、高度、装配空间需接入三维 CAD 内核，当前为 null。

## BOM 导出合同 v1

UTF-8（允许 BOM 标记），逗号分隔 CSV，表头为 `refdes,part_number,value,footprint,description,manufacturer,manufacturer_part_number`。一行对应一个位号，除 refdes 外可为空；含多个位号的导入单元格使用逗号或分号分隔，数量列 `quantity`/`qty`/`数量` 如果存在必须与位号数一致。位号大小写不敏感且不可重复。支持 `Reference`、`Designator`、`位号` 等常见表头别名。未知列暂不保留；变体、DNP 与替代料需后续扩展合同。使用 `import_bom(path)` 和 `export_bom(path, rows)`，导出为 UTF-8 BOM 方便 Excel 打开。
